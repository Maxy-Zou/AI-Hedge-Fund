<objective>
Build the entity resolution engine that maps SEC company names to aliases across data sources (patent assignee, GitHub org, employer names) using fuzzy string matching with rapidfuzz.

Purpose: Entity resolution is the critical path blocker for all multi-signal scoring. Without it, the system cannot connect a company's SEC filings to its patents, GitHub repos, or job postings. This plan builds the name normalization pipeline and fuzzy matching resolver that the universe builder (Plan 04) will use to populate Company.aliases.

Output: Name normalizer module, entity resolver with configurable fuzzy threshold, full unit test coverage.
</objective>

    1. Create `src/ai_washer/entity/resolver.py` (~200 lines):

       Import from rapidfuzz: `from rapidfuzz import fuzz, process`
       Import from entity package: `from ai_washer.entity.normalizer import normalize_company_name`
       Import types: `from ai_washer.entity.types import AliasesSchema, EntityResolutionResult, ResolutionMetadata, ResolutionMethod`

       Create class `EntityResolver`:
       - `__init__(self, threshold: int = 85, high_confidence_threshold: int = 95)`: Store thresholds. Validate threshold >= 50 and <= 100.
       - `resolve_entity(self, sec_name: str, cik: str, candidates: dict[str, list[str]] | None = None, ticker: str | None = None) -> EntityResolutionResult`:
         1. Normalize SEC name via normalize_company_name(sec_name)
         2. Initialize aliases dict: cik=cik, patent_assignee=[], github_org=None, employer_names=[]
         3. Track overall confidence as list of per-source scores
         4. If candidates provided, for each source ("patent_assignee", "employer_names"):
            a. Normalize each candidate name
            b. Use process.extractOne(normalized_sec, normalized_candidates, scorer=fuzz.token_sort_ratio, score_cutoff=self.threshold)
            c. If match found, add the ORIGINAL (unnormalized) candidate name to aliases[source] list
            d. Track match score
         5. For "github_org" source: exact match after lowering + stripping (no fuzzy -- GitHub org names are short slugs)
         6. Calculate overall confidence: mean of match scores (or 0.0 if no candidates tried)
         7. Set needs_review = (any match score between threshold and high_confidence_threshold)
         8. Build ResolutionMetadata(resolved_at=date.today(), method=ResolutionMethod.AUTOMATED_FUZZY, confidence=overall_confidence/100, needs_review=needs_review)
         9. Build AliasesSchema from aliases dict + metadata
         10. Return EntityResolutionResult(sec_name=sec_name, matched_cik=cik, ticker=ticker, resolved_aliases=aliases_schema)
       - `resolve_batch(self, entities: list[tuple[str, str, str | None]], candidates: dict[str, list[str]] | None = None) -> list[EntityResolutionResult]`:
         Takes list of (sec_name, cik, ticker) tuples. Calls resolve_entity for each. Returns list. Use structlog to log progress every 50 entities.

       Create convenience function:
       ```python
       def resolve_entity(sec_name: str, cik: str, candidates: dict[str, list[str]] | None = None, threshold: int = 85) -> EntityResolutionResult:
           resolver = EntityResolver(threshold=threshold)
           return resolver.resolve_entity(sec_name, cik, candidates)
       ```
