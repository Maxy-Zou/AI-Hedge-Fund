<!-- Pipeline execution flow (from research) -->

Stage order in daily_pipeline_flow():
  1. collect_sec_filings_stage  — 10-K, 10-Q, 8-K from EDGAR
  2. collect_patents_stage      — USPTO PatentsView API (may fail — acceptable)
  3. collect_github_stage       — GitHub REST API (rate-limited without token)
  4. collect_earnings_stage     — EarningsCall API transcripts
  5. collect_jobs_stage         — python-jobspy scraper
  6. score_all_stage            — ScoringOrchestrator.score_all() (writes daily_scores)
  7. compute_composites_stage   — calls score_all() again (idempotent — no duplicates)

Stage isolation: each stage wrapped in try/except — one stage failing does NOT stop others.

Known: compute_composites_stage calls score_all() twice — idempotency prevents duplicates
but doubles runtime for scoring pass. Acceptable. Do not file as bug — noted in RESEARCH.md.

EDGAR rate limit: 10 req/sec. Budget 4-10 hours for full run on 100-300 companies.

DailyScore schema key fields:
  - company_id (FK to companies)
  - composite_score (SmallInteger 0-100)
  - scored_at (DateTime with timezone — partition key)
  - signal_breakdown (JSONB)
  - run_id (UUID — links to pipeline_runs)
</interfaces>

    ```bash

      -c "SELECT EXTRACT(YEAR FROM scored_at) as yr,
                 EXTRACT(MONTH FROM scored_at) as mo,
                 COUNT(*) as scores
          FROM daily_scores
          GROUP BY yr, mo ORDER BY yr, mo;"
    ```
    Expected: rows spanning at least 12 calendar months.

    ```bash
    psql "postgresql://hedge:hedge@localhost:5432/ai_hedge_fund" \
      -c "SELECT c.ticker, ds.composite_score, ds.confidence, ds.scored_at::date
          FROM daily_scores ds JOIN companies c ON ds.company_id = c.id
          ORDER BY ds.composite_score DESC LIMIT 20;"
    ```
    Expected: composite_score values between 0 and 100, real tickers visible.
