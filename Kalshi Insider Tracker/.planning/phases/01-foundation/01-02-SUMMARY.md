# Phase 01 Plan 02: Database Layer — ORM Models and Initial Alembic Migration

**One-liner:** SQLAlchemy 2.0-style ORM with AppendOnlyMixin (UUID PK + created_at, no update/delete), 4 models (Market mutable, MarketSnapshot/Signal/Trade append-only), JSONB columns, SmallInteger prices, and a hand-written Alembic migration creating all tables verified via testcontainers PostgreSQL.

## What Was Built

### Database Base Layer (`src/kalshi_tracker/db/base.py`)

- `Base` — SQLAlchemy `DeclarativeBase` for all models
- `AppendOnlyMixin` — UUID primary key + `created_at` (timezone=True). No `update()` or `delete()` methods. Kalshi-adapted: no `DualTimestampMixin` since this is a real-time system, not a batch pipeline. LOG-03 compliant.

### ORM Models (`src/kalshi_tracker/db/models.py`)

| Model | Table | Type | Key Columns |
|-------|-------|------|-------------|
| `Market` | `markets` | Mutable entity | ticker (PK), series_ticker, title, status, close_time, first_seen, last_updated (onupdate) |
| `MarketSnapshot` | `market_snapshots` | Append-only | id (UUID), captured_at, yes_bid/ask, no_bid/ask, last_price (SmallInteger), volume, raw_snapshot (JSONB) |
| `Signal` | `signals` | Append-only | id (UUID), detected_at, ticker, signal_type, confidence, details (JSONB) |
| `Trade` | `trades` | Append-only | id (UUID), placed_at, ticker, side, contracts, price_cents (SmallInteger), mode, status, kalshi_order_id |

**Invariants enforced:**
- Prices stored as `SmallInteger` (0-99 integer cents) — never floats
- All `DateTime` columns use `timezone=True` (UTC)
- `JSONB` from `sqlalchemy.dialects.postgresql` (not generic `JSON`)
- `Market.last_updated` has `onupdate=func.now()` for mutable upsert tracking

### Session Factory (`src/kalshi_tracker/db/session.py`)

- `create_engine_from_settings(settings: AppSettings) -> Engine` — creates sync engine from `KALSHI_TRACKER_DATABASE_URL`
- `get_session_factory(engine: Engine) -> sessionmaker[Session]` — session factory with `expire_on_commit=False`

### Alembic Migration (`src/kalshi_tracker/db/migrations/`)

- `env.py` — reads `KALSHI_TRACKER_DATABASE_URL`, imports `Base` + models, sets `target_metadata`, uses `kalshi_tracker_alembic_version` table
- `0001_initial_schema.py` — revision `0001`, creates all 4 tables with correct indexes and JSONB columns

## Decisions Made

1. **No DualTimestampMixin** — The sibling project (AI Washing Detector) uses `as_of_date`/`observed_date` for batch pipelines. Kalshi Insider Tracker is real-time polling, so domain-specific timestamps (`captured_at`, `detected_at`, `placed_at`) are used directly. `AppendOnlyMixin` has only `id` and `created_at`.

2. **Hand-written migration (not autogenerate)** — `alembic revision --autogenerate` requires a live database connection at generation time. Using a placeholder URL fails when psycopg2 isn't installed or the URL scheme doesn't match. Writing the migration manually gives a deterministic revision ID (`0001`) and avoids dev environment setup friction.

3. **PYTHONPATH + venv alembic path in integration tests** — The venv uses Python 3.13 (uv-managed), but the shell activates the system Python 3.12. The `.pth` file in site-packages correctly points to `src/`, but it only works with the venv's Python binary. Tests use `PYTHONPATH=src` and the explicit `.venv/bin/alembic` path to ensure the subprocess uses the correct environment.

4. **`pytestmark = pytest.mark.integration` (not bare expression)** — The original plan had `pytest.mark.integration` as a bare expression, which ruff B018 flags as a useless expression. Corrected to `pytestmark = ...` which pytest recognizes for test collection filtering.
